# Karaoke TV — прогресс разработки

Дата обновления: 2026-11-02

## Реализовано

### Сравнение с Antigravity: источники

- Оригинал D:/Desktop/Проекты/Антигравити/Караоке только читался. YouTubeSource использует search/videos Data API с apiKeyProvider; VkVideoSource использует video.search/video.get с tokenProvider. Без авторизации эти два адаптера сами возвращают ошибку. Пользователь подтвердил работу установленного Antigravity; конфигурация этого установленного приложения здесь неизвестна. Секреты не читались/не переносились.
- RutubeSource использует https://rutube.ru/api/search/video/?query=...&format=json без ключа. Этот адрес теперь default Codex с возможностью переопределения. Стабильный официальный контракт не подтверждён: интеграция экспериментальная, поддерживаемая альтернатива — согласованный партнёрский API или внешний официальный поиск (не равно интеграции).
- Исправлено отклонение официальных VK embed-ссылок vk.com/video_ext.php; проверяются точные HTTPS host/path, не строковый префикс. Фильтруются удалённые/заблокированные результаты RUTUBE.
- Перенесён Gson-конвертер Antigravity: прежний Moshi не имел Kotlin adapter/codegen для DTO. Добавлен общий таймаут 20 с и изоляция выброшенных исключений провайдеров.
- Room/schema не менялись. Очередь получает прежнюю KaraokeVersion; функциональное сохранение и воспроизведение на устройстве не проверены.

- Если отсутствует приложение для внешнего URL, показывается сообщение вместо падения.

- Исправлено добавление локальной песни в очередь: `song.id` больше не используется ошибочно как `versionId`; DAO выбирает лучшую сохранённую версию песни.
- Если для локальной песни нет сохранённой версии, запись в очередь не создаётся.
- Исправлено сохранение повторно найденной версии: обновление больше не удаляет строку и не ломает ссылки очереди.
- Очередь теперь показывает название и источник версии, а телефон получает обновления после операций с очередью.
- Воспроизведение поддерживает embedded и внешний официальный URL с валидацией адреса.
- Добавлены безопасное экранирование JSON для удалённой очереди и проверка идентификатора видео перед построением embed URL.
- WebView теперь запрещает файловый/контентный доступ и mixed content, корректно уничтожается при закрытии; внешние ссылки принимаются только с официальных доменов источника.
- YouTube-адаптер теперь умеет получать детали видео, длительность и статус embeddable; успешные поисковые запросы сохраняются в историю.
- Запуск локального управления теперь обрабатывает ошибки без падения приложения и показывает их в настройках.
- Единый поиск теперь запускает YouTube, VK Видео и RUTUBE-адаптер параллельно; VK использует официальный токен, RUTUBE — полный URL явно настроенного одобренного партнёрского endpoint. Частичный отказ одного источника не скрывает результаты остальных.
- Добавлен LRC-парсер, сохранение таймкодов текста в версии песни и синхронизированный overlay через официальный YouTube IFrame API; для VK/RUTUBE текст появляется только если источник отдаёт таймкоды в описании.
- История выступлений теперь отображается в разделе очереди с участником, названием песни и статусом.
- Возврат из встроенного плеера теперь помечает соответствующее выступление завершённым через Activity Result и Room.
- Добавлены избранные песни с переключателем в очереди и локальным хранением в Room.
- VK-результаты используют официальный embed URL, когда API его возвращает; иначе открывается официальный внешний просмотр.
- Добавлен измеряемый монитор микрофона: RMS/уровень сигнала и оценка стабильности тона отображаются во время выступления, итоговый технический балл сохраняется в истории при выданном разрешении RECORD_AUDIO. Это не заявляет автоматическую оценку художественного качества вокала.
- Добавлен Gradle Wrapper 8.11.1; проект настроен на установленный Build-Tools 35.0.0.

## Осталось

- Нижняя панель главного Activity пока не является сохраняющим воспроизведение мини-плеером: отдельный PlayerActivity закрывает основной экран. Требуется общий playback host и реальное состояние play/pause; предыдущую запись о готовности мини-плеера не считать функциональной проверкой.
- Проверить и улучшить карточки поиска на узких телефонах.

- Запустить полный `test` только в отдельном окружении/цикле с контролируемым Maven-кэшем.
- Добавить тест DAO для сценария локальной песни без версии и сценария выбора лучшей версии.
- Подключить реальные ключи/одобренный endpoint в локальной конфигурации и проверить ответы каждого источника на устройстве.
- Проверить LRC-синхронизацию и завершение выступления на Android TV устройстве.
- Выполнить физический smoke-test смартфона: запуск из launcher, ввод запроса, прокрутка, запуск официального просмотра и возврат из плеера.
- На реальном устройстве проверить фокусировку D-pad в боковом меню, мягкую клавиатуру в крупной строке поиска и кликабельность карточек с реальными результатами.

## Следующий шаг

Установить собранный APK на смартфон/Android TV и выполнить smoke-test; затем подключить тестовые ключи и одобренный endpoint только в локальной конфигурации для проверки ответов каждого источника.
